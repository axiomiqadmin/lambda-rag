# Dynamic Document Ontology v1: Current Implementation

**Status:** Deterministic pipeline implementation in progress. This is not a semantic extraction or production-readiness claim.

## Offline Compile

The deterministic fake emits one candidate concept per unique changed body-span fingerprint. It exists to exercise schema, provenance, reconciliation, storage, replay, and CLI paths without an external model:

```powershell
dotnet run --project src/LambdaRag.Cli/LambdaRag.Cli.csproj -- ontology compile `
  --document samples/architecture/Cloud-service-Architecture.docx `
  --namespace sample-architecture `
  --registrant acceptance `
  --salt cloud-service-architecture-v1 `
  --version v1 `
  --snapshot-id cloud-service-architecture-local-v1 `
  --artifacts artifacts/sample-run `
  --fake-generator
```

The family namespace, registrant, and salt define the document-family ID. The version label identifies the parsed version; snapshot ID names the accepted artifact version. Incremental compilation uses `--parent <snapshot-id>` and requires the parent's stored canonical document/span records.

Without `--fake-generator`, `compile` is cache/replay only and fails closed when no matching candidate request exists. There is no live LLM/Azure adapter in this implementation.

## Replay and Inspection

For a candidate first generated by the fake, provide its generator identity on replay:

```powershell
dotnet run --project src/LambdaRag.Cli/LambdaRag.Cli.csproj -- ontology replay `
  --document samples/architecture/Cloud-service-Architecture.docx `
  --namespace sample-architecture `
  --registrant acceptance `
  --salt cloud-service-architecture-v1 `
  --version v1 `
  --snapshot-id cloud-service-architecture-local-v1 `
  --artifacts artifacts/sample-run `
  --generator-id deterministic-document-span-fake/1.0.0
```

Inspect, compare, or validate artifacts without generation:

```powershell
dotnet run --project src/LambdaRag.Cli/LambdaRag.Cli.csproj -- ontology inspect <accepted-snapshot.json>
dotnet run --project src/LambdaRag.Cli/LambdaRag.Cli.csproj -- ontology diff <old-snapshot.json> <new-snapshot.json>
dotnet run --project src/LambdaRag.Cli/LambdaRag.Cli.csproj -- ontology validate <artifact.json>
```

Artifacts are stored under `artifacts/<family-id-prefix>/documents/<document-fingerprint-prefix>/versions/<version-id-hash-prefix>/`. Full fingerprints remain inside artifacts. Writes are atomic and immutable; a byte-identical retry is accepted, a conflicting overwrite is rejected.

## Opt-In Projection

Static maps remain the default. CLI `project` and `review` can use an accepted snapshot explicitly:

```powershell
dotnet run --project src/LambdaRag.Cli/LambdaRag.Cli.csproj -- project `
  --document samples/architecture/Cloud-service-Architecture.docx `
  --out artifacts/sample-run/dynamic-projection.json `
  --ontology-snapshot <accepted-snapshot.json> `
  --ontology-mode dynamic
```

`hybrid` merges accepted labels/aliases into a selected static map and fails on ambiguous normalized phrases. `static` remains backwards-compatible. API `/review` accepts optional `ontologySnapshotPath`, `ontologyMode`, and `topicMap` fields; omitted fields preserve the static default. No generator is invoked by projection or evaluation. The API dynamic path was smoke-tested using the Cloud-service Architecture DOCX snapshot with the small cloud ruleset.

## Human-Reviewed Reference

[The selected DOCX reference fixture](../tests/Goldens/cloud-service-architecture-ontology-reference.json) records the user's ten concepts, seven relationships, and six negative expectations. It is independent reference data, not generated output, an exhaustive ontology, or an accepted compiler snapshot. Domain types and relationship phrases are preserved without silently mapping them to the runtime relationship allow-list; relationship endpoints may name entities outside the selected ten concepts.

The existing DOCX acceptance suite now verifies the reference's evidence fragments against parsed canonical text, the Compliance Service catalog citation within a single table row, and the minimum-replica column for Fraud Detection, Notification, and Compliance. These three rows specify two replicas while the general production requirement specifies three. The reference requires surfacing that conflict, not choosing a value automatically.

Table-cell composites and abbreviated quotations are recorded explicitly. The submitted secrets quotation ends before a parenthetical in the source; its contiguous source fragment is used for grounding, with the submitted wording retained. Passing these checks validates reference citations, not the generator's ability to discover concepts, enforce negative expectations, or detect contradictions. Semantic output comparison remains unimplemented.

## Evidence and Limits

- `artifacts/golden/` and `artifacts/sample-run/` are generated using the deterministic fake. They validate pipeline behavior and provenance shape, not concept correctness.
- Fake labels are normalized span text; they are not reviewed concepts, entity extraction, or relationship discovery. The fake currently emits no relationships.
- `scripts/ontology_benchmark.ps1` measures deterministic pipeline diagnostics across ten text variants. Delta precision, unsupported-concept rate, and verdict stability require independent labels and remain null/unclaimed.
- Ambiguous span identity blocks candidate generation/publication. Candidate evidence is resolved against canonical parsed spans before reconciliation.
- Snapshot IDs are caller-supplied. No actual provider, deployment identity, or live structured-output behavior has been tested.
- Existing idempotency tests include a bootstrap-only benchmark skip and a ruleset-pull skip blocked by existing issue #72. The strict no-skips quality gate therefore reports failure/incomplete status rather than hiding them.
